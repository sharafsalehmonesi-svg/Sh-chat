# Sh-chat — نسخة الويب المتصلة بـ Supabase

هذه النسخة تحتوي على واجهة عربية متجاوبة ومتصلة بمشروع Supabase الحالي. تدعم:
- إنشاء حساب وتسجيل الدخول بالبريد الإلكتروني وكلمة المرور (قد يُطلب تأكيد البريد الإلكتروني).
- عرض المنشورات المشتركة.
- نشر نص أو صورة.
- الإعجاب وإلغاء الإعجاب.
- التعليقات.
- حذف المنشور الذي أنشأه المستخدم.
- البحث في المنشورات ومشاركة رابط/تفاصيل المنشور.

## 1) نشرها على GitHub Pages
1. افتح مستودع GitHub المسمى `sh-chat`.
2. افتح `index.html` الموجود في المستودع، واختر Edit (رمز القلم).
3. استبدل محتوى الملف بمحتوى `index.html` الموجود في هذه الحزمة، ثم اضغط Commit changes.
   - أو ارفع الملف من Add file > Upload files، مع التأكد أن اسمه `index.html` في جذر المستودع.
4. افتح Settings > Pages، وتأكد أن النشر من الفرع الرئيسي (`main`) ومن المجلد الجذر (`/root`).
5. افتح رابط GitHub Pages الخاص بالمستودع. استخدم HTTPS.

## 2) إعداد التسجيل بالبريد الإلكتروني
1. في Supabase افتح المشروع الحالي ثم Authentication > Sign In / Providers > Email، وتأكد أن Email provider مفعّل.
2. خيار Confirm email مفعّل في الإعداد الظاهر لديك؛ لذلك على المستخدم فتح رسالة التأكيد قبل تسجيل الدخول إذا طلب Supabase ذلك.
3. افتح Authentication > URL Configuration وأضف رابط موقع GitHub Pages في Site URL وRedirect URLs، مثل رابط الموقع المنشور الفعلي. لا تضع رابط المستودع إذا كان رابط Pages مختلفًا.
4. لا يحتاج تسجيل البريد الإلكتروني إلى Twilio أو رسائل SMS.

## 3) تفعيل رفع الصور
1. افتح Supabase > SQL Editor > New query.
2. افتح `setup-image-storage.sql` من هذه الحزمة وانسخ محتواه إلى محرر SQL.
3. اضغط Run.
4. تأكد أن Bucket اسمه `post-images` موجود في Storage.
5. جرّب النشر بعد تسجيل الدخول. الحد الحالي للصورة 5 ميغابايت.

## 4) قاعدة البيانات والصلاحيات
الواجهة تعتمد على الجداول الموجودة مسبقًا:
- `profiles` بالأعمدة `id`, `username`, `full_name`
- `posts` بالأعمدة `id`, `user_id`, `content`, `image_url`, `created_at`
- `comments` بالأعمدة `id`, `post_id`, `user_id`, `content`, `created_at`
- `likes` بالأعمدة `post_id`, `user_id`

يجب أن تكون سياسات Row Level Security (RLS) مفعّلة ومضبوطة بحيث:
- يستطيع الجميع قراءة المنشورات والتعليقات والإعجابات العامة.
- لا ينشر أو يعلّق أو يعجب إلا المستخدم المسجّل.
- لا يعدّل أو يحذف المستخدم إلا بياناته الخاصة.
- تمنع `likes` تكرار الإعجاب من المستخدم نفسه بالمنشور نفسه (مفتاح فريد على `post_id`, `user_id`).

## تنبيه أمني
الواجهة تستخدم Project URL وPublishable key فقط، وهو مفتاح عميل مخصص للاستخدام العام مع RLS. لا تضع `service_role` أو أي مفتاح سري في HTML أو GitHub. لا تعتبر الموقع جاهزًا للإطلاق العام قبل اختبار سياسات RLS وتسجيل الدخول والرفع بحسابين مختلفين.
